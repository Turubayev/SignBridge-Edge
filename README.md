## 📌 О проекте
**SignBridge-Edge** — автономная система распознавания **казахско-русского жестового языка (КРЖЯ)** и перевода в текст и речь. Работает полностью на устройстве (компьютер, смартфон, Raspberry Pi, браузер) без интернета, поэтому видео никогда не покидает устройство.

> **Статус: рабочий прототип конвейера.** Трекинг (MediaPipe Holistic), нормализация, модель, экспорт в ONNX, демо с веб-камеры, браузерная версия, перевод глоссов в текст на русском и казахском, запись данных с согласием участников и отчёт о справедливости работают.
>
> **Чего пока нет — реальной модели КРЖЯ.** Модель в `models/` обучена на **процедурной синтетике** (условные «жесты» с известными классами), чтобы конвейер запускался сразу. Настоящие жесты она **не распознаёт**. Для реальной модели нужны датасет K-RSL (Назарбаев Университет, по запросу у авторов) и записи носителей КРЖЯ — инструменты для этого в репозитории есть (см. «Как получить реальную модель»).

## 🎯 Решаемая проблема
Глухие и слабослышащие люди сталкиваются с барьерами в поликлинике, ЦОНе, банке, учебном заведении. Сурдопереводчиков не хватает, особенно за пределами крупных городов. Проект даёт инструмент для коротких бытовых диалогов там, где переводчика нет.

> **Проект не заменяет профессионального сурдопереводчика**, особенно в медицинских, юридических и других ситуациях, где цена ошибки высока.

## 🤝 Принцип «Ничего о нас без нас»
* носители КРЖЯ участвуют в сборе данных, разметке и тестировании;
* приоритет сценариев определяют сами пользователи (`data/vocab/glosses.json` — стартовый список для обсуждения);
* участники получают вознаграждение и указываются как соавторы датасета;
* запись — только с информированного согласия и с правом его отозвать (`scripts/record_samples.py --revoke`).

## ✅ Что реализовано

| Нормализация (центр и масштаб по плечам, локальные координаты кистей, 48 кадров), аугментация, зеркалирование для левшей | `signbridge/features.py` |
| Классификатор: Transformer-энкодер по последовательности точек, экспорт ONNX | `signbridge/model.py`, `scripts/train.py` |
| Разделение потока на жесты по движению рук; немануальные маркеры (поднятые брови → вопрос, покачивание головой → отрицание) | `signbridge/segmenter.py` |
| Глоссы → текст RU/KZ: правила для сценариев ЦОНа и поликлиники, падежи, казахские аффиксы с сингармонизмом; склейка дактиля в имена; опционально — локальная LLM | `signbridge/gloss2text.py` |
| Полный **казахский дактиль** (42 буквы, включая ә, ғ, қ, ң, ө, ұ, ү, һ, і), словарь хранится отдельно от модели | `data/vocab/dactyl_kk.json` |
| Бытовой словарь MVP: 60 глоссов (ЦОН, поликлиника, банк) с переводами RU/KZ | `data/vocab/glosses.json` |
| Демо с веб-камеры + офлайн-озвучивание | `run_demo.py` |
| **Браузерная версия** (MediaPipe Tasks for Web + ONNX Runtime Web) — сервер только раздаёт статику | `web/` |
| Запись данных (только координаты, не видео) с проверкой согласия; конвертация видеодатасетов (K-RSL) | `scripts/record_samples.py`, `scripts/prepare_krsl.py` |
| Проверка по исполнителям, не встречавшимся в обучении; точность по группам и Model Card | `signbridge/dataset.py`, `docs/MODEL_CARD.md` |
| Экспорт: ONNX INT8, LiteRT (через onnx2tf), ExecuTorch; замер задержки | `scripts/export.py`, `docs/EXPORT.md` |

## 📊 Демо-модель (синтетика)
102 класса (60 глоссов + 42 буквы дактиля), 24 синтетических «исполнителя», проверка на 5 исполнителях, не встречавшихся в обучении:

| Метрика | Значение |
|---|---|
| Top-1 / Top-5 | 1.00 / 1.00 |
| Задержка ONNX Runtime, CPU (окно 48 кадров) | **1.4 мс** (браузер, WASM: ~50 мс на первый вызов) |
| Размер модели | 1.9 МБ (ONNX float32) |
| Разрыв точности между группами | 0 п.п. |
| Расхождение нормализации JS (браузер) и Python | < 2·10⁻⁶ |

Точность 100 % значит только то, что синтетические «жесты» легко различимы и конвейер (трекинг → признаки → модель → ONNX) собран без ошибок. **О качестве на реальном КРЖЯ эти цифры ничего не говорят.** Задержка и размер модели реальны и сохранятся на реальных данных той же архитектуры.

## 🚀 Быстрый старт
```bash
git clone https://github.com/Turubayev/SignBridge-Edge.git
cd SignBridge-Edge
python -m venv .venv && source .venv/bin/activate
pip install --extra-index-url https://download.pytorch.org/whl/cpu -r requirements.txt

python scripts/download_models.py                     # MediaPipe Holistic Landmarker (~13 МБ)
python run_demo.py --model models/krsl_isolated.onnx  # демо с веб-камеры (Q — выход, L — RU/KZ)

# Браузерная версия (камера доступна на localhost или по HTTPS)
python -m http.server 8080 --directory web            # → http://localhost:8080
pytest -q
```
Браузерную версию можно опубликовать на GitHub Pages (папка `web/`) — обработка всё равно идёт на устройстве пользователя.

## 🧠 Как получить реальную модель
```bash
# 1. Согласия участников: скопируйте шаблон и заносите номера подписанных согласий
cp data/consent_registry.template.csv data/consent_registry.csv
# 2. Запись носителями КРЖЯ (сохраняются только координаты ключевых точек)
python scripts/record_samples.py --signer S001 --consent C2026-001 --gloss СПАСИБО --n 10 \
    --skin-tone III-IV --lighting хорошее --device веб-камера --age 30–55 --hand right
# 3. (по желанию) K-RSL или другой видеодатасет → ключевые точки
python scripts/prepare_krsl.py --src /path/to/K-RSL --dst data/recordings
# 4. Обучение, проверка по новым исполнителям, отчёт о справедливости, экспорт ONNX (+ копия в web/models)
python scripts/train.py --data data/recordings --epochs 60
python scripts/export.py --onnx models/krsl_isolated.onnx --int8 --benchmark
```
Минимум для осмысленной модели — 10–20 исполнителей разного возраста, пола, тона кожи, левши и правши, по 5–10 повторов каждого жеста в разных условиях освещения.

## ⚙️ Архитектура
```
Камера ─▶ Holistic Landmarker ─▶ Нормализация точек ─▶ Сегментация по движению ─▶ Модель жестов ─▶ Глоссы
                                                                                                   │
                     Экран / TTS (RU, KZ) ◀── Текст ◀── Глоссы → текст (правила / локальная LLM) ◀─┘
```
На модель передаются только координаты, а не изображение.

### Три варианта развёртывания
| Вариант | Где работает | Как |
|---|---|---|
| Браузер | Планшет или компьютер в ЦОНе, больнице, акимате | `web/` (статический сайт) |
| Мини-ПК / Raspberry Pi | Киоск-терминал | `run_demo.py` + ONNX Runtime |
| Мобильное приложение | Смартфон | LiteRT / ExecuTorch (`docs/EXPORT.md`), Flutter — в roadmap |

> Серверная обработка видео **не используется**: это противоречит принципу приватности проекта. Локальная LLM для перевода глоссов принимается только по адресу `localhost`.

## ⚖️ Справедливость и проверка смещений
Качество трекинга может зависеть от тона кожи, освещения и камеры. Проект **не заявляет отсутствие смещений**, а измеряет их: `scripts/train.py` считает точность отдельно по тону кожи, освещению, устройству, возрасту и рабочей руке и пишет её в `docs/MODEL_CARD.md`. Цель — разрыв между группами не более 5 п.п.

## 📏 Метрики
| Метрика | Где считается |
|---|---|
| Top-1 / Top-5 на исполнителях, не встречавшихся в обучении | `scripts/train.py` |
| Задержка (мс) на целевом устройстве | `scripts/train.py`, `scripts/export.py --benchmark` |
| Разрыв точности между группами | `docs/MODEL_CARD.md` |
| WER по глоссам (непрерывная речь) | этап исследования |
| Оценка пользователей | тестирование с носителями КРЖЯ |

## 🔐 Приватность
* Обработка только на устройстве; видео не сохраняется и не передаётся.
* Записи для датасета — только координаты, с согласием и правом отзыва; записи людей в публичный репозиторий не попадают (`.gitignore`).

## 🚧 Ограничения
* Нет реальной модели КРЖЯ до сбора данных (см. выше).
* Словарь MVP ограничен бытовыми темами; конфигурации дактиля нужно описать вместе с носителями языка.
* Непрерывная речь и перевод «текст → жест» (аватар) — исследовательские задачи.
* Правила «глоссы → текст» покрывают типовые фразы; для свободных высказываний нужна языковая модель.
* Речь собеседника (ASR) пока не реализована: в браузере встроенное распознавание отправляет звук в облако, а это противоречит принципу приватности. Нужна локальная модель.
